JAMPO CUP v38 — 公開サイト・管理者認証・全員共通データ

このZIPには既存のサイト機能を維持したHTMLファイルと、Supabase共通データ同期用ファイルを含みます。
重要：ZIPをアップロードしただけでは公開運用は完成しません。Supabaseを設定してからGitHub Pagesへ公開してください。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
完成後の仕組み
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
・閲覧用サイト：URLを知っている人なら誰でも閲覧可能
・管理画面：Supabaseで作成し、管理者として許可したアカウントだけが編集可能
・共通データ：選手、チーム、ランキング、日程、お知らせ、アイコン等をSupabaseに保存
・更新反映：公開ページは30秒ごとに共有データを確認し、変更があれば更新
・認証：HTMLにパスワードを埋め込まず、Supabase Authを使用
・データベース側でも管理者許可リスト（jampo_admins）を確認し、未許可ユーザーの書き込みを拒否

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Supabaseプロジェクトを作る
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) https://supabase.com/ を開き、アカウントを作成して New project を選択します。
2) プロジェクト名を JAMPO CUP などにして作成します。データベースパスワードは安全なものを設定し、保管してください。
3) Project Settings > API（または Connect）から Project URL と公開用 anon / publishable key を確認します。
4) このZIPの supabase-config.js をテキストエディタで開き、以下を書き換えます。
   window.JAMPO_SUPABASE_URL = 'https://YOUR-PROJECT.supabase.co';
   window.JAMPO_SUPABASE_ANON_KEY = 'YOUR_SUPABASE_ANON_KEY';
   URLと公開用 anon/publishable key を設定してください。service_role / secret key は絶対に入力しないでください。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. データベースのテーブルと権限を作る
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) Supabase Dashboard の SQL Editor を開きます。
2) ZIP内の supabase-setup.sql を開き、全文を貼り付けて Run を押します。
3) エラーがないことを確認します。
このSQLは公開閲覧を許可しますが、データの書き込みは jampo_admins に登録されたユーザーだけに制限します。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. 管理者アカウントを作成し、管理者許可リストに登録
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) Supabase Dashboard > Authentication > Users を開きます。
2) Add user / Create new user から管理者のメールアドレスと、十分に強いパスワードを設定してユーザーを作成します。
3) 作成したユーザーの詳細に表示される User UID（UUID）をコピーします。
4) SQL Editorで、次のSQLの UUID_HERE を実際のUser UIDに置き換えて実行します。
   insert into public.jampo_admins (user_id) values ('UUID_HERE') on conflict (user_id) do nothing;
5) Authenticationの設定で一般ユーザーのEmail sign-up（新規登録）を無効にしてください。設定項目名はSupabaseの画面更新で異なる場合があります。
6) 管理者許可リストに登録されていないアカウントは、ログインしても編集できません。

重要：以前指定された「11224433」は短く推測されやすいため、この公開版では使いません。Supabaseで設定する強い管理者パスワードを使ってください。パスワードをHTMLファイルに書き込まない構成です。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. GitHub Pagesで公開する
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) GitHubで新しいリポジトリを作成します（例：jampo-cup）。Publicリポジトリにすると、ソースファイルも誰でも閲覧できる点に注意してください。公開サイトのHTML/JSはもともと閲覧可能ですが、秘密情報を含めないでください。
2) ZIPを解凍し、次のファイルをリポジトリの一番上（ルート）にアップロードします。
   index.html
   players.html
   ranking.html
   admin.html
   team.html
   supabase-config.js
   cloud-sync.js
   README.txt（任意）
   supabase-setup.sql（公開サイトには必須ではありません。保管用に別の場所に置いても構いません）
3) GitHubリポジトリの Settings > Pages を開き、Build and deploymentで Deploy from a branch を選び、main / root を指定して保存します。
4) 公開URLが表示されたら index.html を開きます。リンクを知っている人なら誰でも閲覧できます。
5) ヘッダーの「管理者ログイン」を押し、手順3で作成した管理者メールアドレスとパスワードでログインします。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. 初回データの共有と確認
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1) 管理者で初回ログインすると、共有データが未作成の場合は現在の管理画面データを初期データとして登録します。
2) 選手・チーム・日程・お知らせ・ヘッダーアイコンなどを編集し、管理画面の各保存ボタンを押します。
3) 公開サイトを別のブラウザやスマートフォンで開き、反映されることを確認します。公開ページは通常30秒以内に変更を検知します。すぐ確認したい場合は再読み込みしてください。
4) ブラウザを閉じる前に保存完了の表示を確認してください。保存に失敗した場合はブラウザの開発者コンソールとSupabaseの設定を確認します。

注意点
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
・実際のSupabaseプロジェクトをこちらで作成・設定することはできないため、プロジェクトURL/keyの入力、SQL実行、管理者ユーザー作成、GitHub Pages公開は手元で行う必要があります。
・anon/publishable keyは公開用キーですが、service_role / secret keyは絶対にフロントエンドへ置かないでください。
・公開データは誰でも読み取れる仕様です。公開してはいけない個人情報を登録しないでください。
・管理者アカウントのメールアドレスとパスワードを他人と共有しないでください。
・画像はデータにBase64で含まれるため、大きな画像や大量の画像を登録すると保存・読み込みが遅くなる場合があります。大規模運用ではSupabase Storageへ画像を分離することをおすすめします。
・GitHub Pagesは静的サイトのホスティング、Supabaseは認証と共通データの保存を担当します。
・ZIPの整合性とJavaScript構文は検査しますが、実際のSupabase情報が未設定のため、クラウドへのログイン・保存・別端末反映はプロジェクト設定後に確認してください。
